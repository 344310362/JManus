## 简介

JManus是一个基于Spring Boot架构的AI代理管理系统，支持计划生成、异步执行、状态跟踪和配置管理等功能。本指南旨在为开发者提供全面的开发指导，涵盖从环境设置到代码贡献的各个方面。

## 开发环境设置

### IDE配置

推荐使用IntelliJ IDEA作为开发IDE。项目基于Maven构建，导入项目时选择`pom.xml`文件即可自动配置项目结构。确保IDE的Java版本设置为17，与项目配置保持一致。

### 代码格式化规则

项目使用Spring Java Format进行代码格式化。在IDE中安装Spring Java Format插件，并在提交代码前运行格式化命令。此外，项目还使用Spotless插件来移除未使用的导入。

### 调试设置

项目包含多个配置文件，位于`src/main/resources/`目录下：
- `application.yml`: 主配置文件
- `application-dev.yml`: 开发环境配置
- `application-docker.yml`: Docker环境配置
- `application-h2.yml`: H2数据库配置
- `application-mysql.yml`: MySQL数据库配置
- `application-postgres.yml`: PostgreSQL数据库配置

启动应用时，可以通过`--spring.profiles.active`参数指定激活的配置文件。例如，使用`--spring.profiles.active=dev`来激活开发环境配置。

## 构建系统

### Makefile概述

项目使用Makefile作为主要的构建工具。根目录下的`Makefile`文件包含了所有构建目标，通过包含`tools/make/`目录下的各个`.mk`文件来组织不同的构建任务。

```makefile
_run:
	@$(MAKE) --warn-undefined-variables \
		-f tools/make/common.mk \
		-f tools/make/java.mk \
		-f tools/make/linter.mk \
		-f tools/make/tools.mk \
		-f tools/make/docker.mk \
		-f tools/make/ui.mk \
		$(MAKECMDGOALS)

.PHONY: _run

$(if $(MAKECMDGOALS),$(MAKECMDGOALS): %: _run)
```

### Java构建脚本

`tools/make/java.mk`文件定义了与Java构建相关的任务：

- `build`: 构建项目，跳过测试
- `test`: 运行测试
- `format-fix`: 格式化代码
- `format-check`: 检查代码格式
- `spotless-apply`: 运行Spotless并应用更改
- `checkstyle-check`: 运行Checkstyle检查

```makefile
.PHONY: test
test: ## Run tests
	@$(LOG_TARGET)
	mvnd test

.PHONY: build
build: ## Build the project
	@$(LOG_TARGET)
	mvnd -Dmvnd.connectTimeout=30000 -B package --file pom.xml -DskipTests=true

.PHONY: format-fix
format-fix: ## Format the code
	@$(LOG_TARGET)
	mvnd -Dmvnd.connectTimeout=30000 spring-javaformat:apply
```

## 代码提交流程与分支策略

### 分支策略

项目采用标准的Git分支策略：
- `main`分支：主分支，包含最新的稳定代码
- 功能分支：从`main`分支创建，用于开发新功能或修复bug
- 发布分支：从`main`分支创建，用于准备发布版本

### 版本发布规范

版本号遵循语义化版本控制规范（Semantic Versioning）。每次发布新版本时，需要在GitHub上创建一个新标签，并填写发布说明。

## 测试策略

### 单元测试

项目使用JUnit 5进行单元测试。测试代码位于`src/test/java`目录下。运行单元测试的命令为`make test`。

### 集成测试

项目使用Spring Boot Test进行集成测试。测试代码同样位于`src/test/java`目录下。集成测试会启动整个Spring应用上下文，测试各个组件之间的交互。

### 端到端测试

前端项目包含端到端测试，使用Cypress框架。测试代码位于`ui-vue3/cypress`目录下。运行端到端测试的命令为`pnpm run test:e2e`。

```json
"scripts": {
    "test:unit": "vitest",
    "test:e2e": "start-server-and-test preview http://localhost:4173 'cypress run --e2e'",
    "test:e2e:dev": "start-server-and-test 'vite dev --port 4173' http://localhost:4173 'cypress open --e2e'"
}
```

## CI/CD流水线

### 自动化测试流程

CI/CD流水线包含以下步骤：
1. 代码检查：运行`make lint`检查代码质量
2. 构建：运行`make build`构建项目
3. 测试：运行`make test`执行单元测试和集成测试
4. 打包：将构建结果打包成Docker镜像
5. 部署：将Docker镜像推送到镜像仓库

### Docker配置

Dockerfile位于`deploy/Dockerfile`，使用多阶段构建来优化镜像大小。基础镜像为Eclipse Temurin 17 JDK，安装了Node.js和Playwright所需的依赖。

```dockerfile
FROM eclipse-temurin:17-jdk-noble

RUN apt-get update && \
    apt-get install -y --no-install-recommends \
        ca-certificates \
        curl \
        gnupg \
        lsb-release \
        software-properties-common \
        wget \
        unzip \
        xvfb \
        x11vnc \
        fluxbox \
        fonts-liberation \
        fonts-dejavu-core \
        fonts-noto-cjk && \
    curl -fsSL https://deb.nodesource.com/setup_18.x | bash - && \
    apt-get install -y --no-install-recommends nodejs && \
    npm install -g playwright && \
    rm -rf /var/lib/apt/lists/*
```

## 代码贡献指南

### 代码风格

遵循Java编码规范，使用Spring Java Format进行代码格式化。提交代码前，请确保代码符合Checkstyle规则。

### 文档要求

- 在提交PR时，需要填写PR模板，清晰描述修改内容和实现的功能
- 对于复杂的功能修改，建议先在Issue中添加Feature标签，并简要描述设计和修改点
- 文档更新应与代码修改同步进行

### 审查流程

1. 提交PR后，CLA机器人会自动检查是否已签署CLA
2. 如果未签署，需要在PR评论中回复`I have read the CLA Document and I hereby sign the CLA`
3. 等待CI检查通过
4. 项目维护者进行代码审查
5. 根据反馈进行修改（如有需要）
6. PR合并后，即成为JManus贡献者

## 性能分析与调试技巧

### 性能分析

使用JVM内置的性能分析工具，如JVisualVM或JProfiler，监控应用的内存使用、CPU占用和线程状态。重点关注数据库查询性能和外部API调用延迟。

### 调试技巧

- 使用`/api/executor/details/{planId}`接口跟踪异步任务进度
- 通过`/api/config/batch-update`修改配置，无需重启服务
- 查看前端实现，如`ExecutionController.vue`和`ExecutionDetails.vue`，了解任务发起和状态跟踪的实现

```bash
# 1. 上传文件（可选）
curl -X POST http://localhost:8080/api/file-upload/upload \
  -F "files=@/path/to/file1.pdf" \
  -F "files=@/path/to/file2.txt"

# 2. 异步执行（使用上传的文件）
curl -X POST http://localhost:8080/api/executor/executeByToolNameAsync \
  -H "Content-Type: application/json" \
  -d '{
    "toolName": "my-tool",
    "serviceGroup": "research",
    "replacementParams": {"param1": "value1"},
    "uploadedFiles": ["file1.pdf", "file2.txt"],
    "uploadKey": "upload-xxx"
  }'

# 3. 获取执行详情（使用返回的 planId）
curl http://localhost:8080/api/executor/details/{planId}
```

### 中文内容检查脚本

项目包含一个Python脚本`tools/scripts/check-chinese-content.py`，用于检查代码中的中文内容。该脚本会扫描Java和前端代码，报告发现的中文内容，并提供修改建议。

```python
def has_real_chinese_content(self, text: str) -> bool:
    """Check if text contains real Chinese content (excluding false positives)"""
    if not (self.chinese_pattern.search(text) or self.chinese_punctuation.search(text)):
        return False

    for pattern in self.exclude_patterns:
        if re.search(pattern, text, re.IGNORECASE):
            temp_text = re.sub(pattern, '', text, flags=re.IGNORECASE)
            if not (self.chinese_pattern.search(temp_text) or self.chinese_punctuation.search(temp_text)):
                return False

    return True
```
